# 2.2절(이론적 배경): 논문 인용 대신 게임 사례를 써도 되는가 — 분석 (2026-09)

> 질문: 목차 개요의 "2장 이론적 배경 → 2.2 익스트랙션 사이클 루프"에서 논문 인용 대신 **게임들을 예시로 가져와도 되나?**
> 전제 문서: `논문_진행_메모.md` §3(목차 개요)·§4 참고문헌 ⑩절, `제목_검토2_메트로베니아_표기범위.md`(청구 범위 원칙)

## 1. 직접 답변

**게임 예시를 가져와도 되며, 이 절에는 오히려 유리하다. 다만 "학술 인용을 전부 게임으로 대체"는 비권고.**

질문은 둘로 나뉘며 답이 다르다:
- **"2.2절에 게임을 사례로 등장시켜도 되나?"** → ✅ 된다, 권장 수준 (§3 방법 C/D)
- **"참고문헌에서 학술 논문을 빼고 게임만 인용해도 되나?"** → ⚠️ 위험 — **최소 3개 앵커(Juul 계열 실패 이론 + Cuerdo 또는 Chang 외 + Zhang)는 유지**하고, 게임은 그 위에 "장르 정의·사례화" 층으로 얹는 하이브리드가 안전

## 2. 근거 (4가지)

### ① 2장의 역할 문제
2장은 이론적 배경이지 장르 소개장이 아니다. 게임 타이틀 자체는 학위 논문 참고문헌에서 **참고문헌이 아니라 "작품(원본 자료)"** 에 해당한다. 게임학에서는 작품을 1차 자료로 인용하는 것은 표준적이지만(`Battlestate Games (2019). Escape from Tarkov [Video game].` 식), 한 절 전체가 작품 나열이면 그 절은 이론적 배경이 아니라 **기획서의 콘텐츠 소개**가 된다 — 교수 코멘트("무슨 기능을 쓰냐지, 콘텐츠 나열 기획서가 아님")에서 경고한 쪽으로 기울 수 있다.

### ② 진행 메모의 자기 규칙
진행 메모 §2 "AI 활용 원칙" 실행 원칙 3번: **"이론적 배경(2장)은 실제 논문/자료를 본인이 찾아 읽고 인용"**. 게임도 예외가 아니라 "자료"에 포함되므로 이 원칙은 그대로 적용된다. 오히려 게임을 인용하면 **그 게임의 루프 구조를 구두시험에서 본문보다 한 단계 깊게 설명할 수 있어야 한다** (§5 리스크). 즉, 게임 인용은 "읽고 인용해야 할 자료의 종류"만 바꿀 뿐 본인이 직접 다뤄야 한다는 부담은 동일하다.

### ③ 분야 현실: 학술 문헌은 적다 — 하지만 '인용 불가'는 아님
익스트랙션 슈터 자체를 주제로 한 논문이 희소해 "게임만 인용해야 하나"라는 생각이 생긴 것인데, 메모에 이미 확보된 자료가 이 문제를 비둘기걸이(二者択一)에서 빼준다:

| 층위 | 맡을 자료 (메모 ⑩절에 이미 있음) | 역할 |
|---|---|---|
| **장르 정의**("익스트랙션 루프가 무엇인가") | **게임 사례**(Tarkov, Lethal Company, Skyhill) + Zhang(2026) | 게임이 채울 빈칸은 정확히 여기 |
| 리스크-보상 구조의 이론적 틀 | Schell *Book of Lenses* "Triangularity"(교재) | 밸런싱 근거 |
| 실패/페널티 설계 | Juul(2013), Chang 외(2017), Cuerdo(2022) | 목숨 3개·사망 페널티의 이론적 정당화 |

특히 **Zhang "Extract"(Parsons BFA 2026)는 그 자체가 Escape from Tarkov에서 영감을 받은 학사급 선례**다. 학술 문헌 쪽에도 이미 게임이 들어가 있는 상태이며, 게임 사례를 추가하는 것은 참고문헌을 빼는 게 아니라 **Zhang가 텍스트로만 그린 루프를 실제 작품들로 실체화해 주는 것**이다.

### ④ 교수 코멘트와의 관계
"무슨 기능을 쓰냐"를 원한다는 코멘트는 게임 사례에 **호의적**이다 — "익스트랙션 구조를 도입했다"는 문장이 Tarkov식 아이템 손실 리스크, Skyhill식 메타진행으로 구체화되면 설계 근거가 살아나기 때문이다. 단, 반대로 **각 게임 사례가 3장의 어떤 구현 결정(목숨 시스템, CycleManager, 특성 선택)과 연결되지 않으면** 그때는 "콘텐츠 나열" 지적을 받는다. → 게임마다 "이 구조를 SubwayExit의 ○○에 반영했다"는 한 줄을 붙이는 것이 방어다.

## 3. 구성 방법 5가지 비교 (최대 5개)

### 방법 A — 학술 인용만 (현행 메모 그대로, 게임 불참)
- **장점**: 참고문헌 형식 안전, "이론적 배경" 요건 충족에 가장 무난
- **단점**: 제목의 핵심 축1인 "익스트랙션 루프"가 2장에서 추상적으로만 처리되고(실패 이론으로 우회 서술), 독자는 이 루프가 구체적으로 무엇인지 3장 구현에서 처음 알게 됨. 제목 ↔ 2장의 괴리
- **적합도**: 낮음~중간 — "익스트랙션"이 제목에 들어온 이상 정의 부재는 감수하기 어려움

### 방법 B — 게임 사례만 (질문하신 그대로)
구성 예: 익스트랙션 게임 정의 → Tarkov 런 구조 분석 → Lethal Company 리스크 이벤트 → Skyhill 메타진행 → SubwayExit 비교
- **장점**: 가장 구체적이고, 본인이 잘 아는 자료라 구두시험 준비가 자연스러움. 교수 코멘트 방향과 일치
- **단점**: (1) 게임만으로는 "이론"이 남지 않아 2장의 성격이 흔들림, (2) 참고문헌에 작품 형식이 없으면 심사자가 출처 확인 불가로 간주할 수 있음, (3) 실패/페널티의 *설계 근거*("왜 목숨 3개인가")를 설명해 줄 이론 부재 — 게임은 "그렇게 하고 있다"까지만 말해줌
- **적합도**: 단독으로 낮음

### 방법 C — 하이브리드 (권고)
구조: `2.2.1 익스트랙션 루프의 정의와 구조(게임 사례 + Zhang/Schell)` → `2.2.2 실패·페널티 설계의 이론적 근거(Juul/Chang 외/Cuerdo)` → `2.2.3 SubwayExit의 위치짓기(Skyhill 비교표 요약, 전문은 3.6으로 이관)`
- **장점**: 게임이 "무엇이다"를 담당하고 논문이 "왜 그런 설계가 유효한지"를 담당 → 2장의 이론성과 구체성을 동시에 확보. 메모 ⑩절 자료는 거의 그대로 쓰고 순서만 재배열
- **단점**: 정의 파트(2.2.1) 작성 분량이 A안보다 늘어남 — 단, 이 부분은 게임 설명이라 작성 난이도는 낮음
- **적합도**: **최고**

### 방법 D — 비교 매트릭스 (C와 병행 권장)
기존 Skyhill 2열 비교표를 **요소 × 게임(Tarkov / Lethal Company / Skyhill / SubwayExit) 4열 매트릭스로 확장**. 행 예시: 전투 방식 / 사망 처리(페널티) / 탈출 조건 / 메타진행 / 기지 기능
- **장점**: "비교"라는 단어 자체가 학술적이고, 심사자가 한 표로 장르 위치를 읽음. 기존 자산(Skyhill 비교표)을 재활용하므로 추가 비용이 적음
- **단점**: 게임의 실제 구조가 프레임에 안 맞으면 억지로 끼워맞추게 됨 — Lethal Company는 익스트랙션 "라이트"(탈출 자체는 간단하고 리스크가 이벤트 의존)라 행 설계 시 주의 필요. **표에 올릴 각 셀은 본인이 직접 확인한 사실로만 채울 것**(AI 활용 원칙과 동일)
- **적합도**: 높음 — C의 2.2.1 또는 2.2.3 안에 표 형태로 삽입

### 방법 E — "참고작품" 별도 목록 형식
게임은 학술 참고문헌과 분리해 **"본 논문에서 인용한 게임 작품"** 목록으로 따로 제시(학술지명/발행사 연도 형식), 본문에서는 (Battlestate Games, 2019) 식으로 인용. 이론은 기존 논문 3~4편만 유지
- **장점**: "사례로 본 작품"과 "학술 문헌"의 위상을 깔끔하게 분리 — 게임학 논문에 흔한 관행. 심사자에게도 의도가 명확히 보임
- **단점**: **학교/학과 형식 규정이 별도 작품 목록을 허용하는지 확인 필요**(많은 학사 논문은 참고문헌에 통합 표기함). 지도교수나 학과 서식 확인 전에는 확정 불가
- **적합도**: 높음 — 단, 학교 규정 확인이 선행 조건

### 결론: **C(하이브리드) + D(매트릭스)를 본문 구성으로, E(작품 목록)는 학교 형식 허용 시 참고문헌 처리로** 조합. B 단독은 회피, A 단독도 비권고.

## 5. 게임 인용 시 구두시험 리스크 및 준비 포인트

1. **"그 게임의 구조를 더 자세히"** — 인용한 각 게임은 본문 서술보다 한 단계 깊게 설명할 수 있어야 한다. 대비 예: Tarkov(탈출점의 일시/영구 구분, 스테쉬 개념), Lethal Company(도즈데이 이벤트가 런 난도를 바꾸는 방식), Skyhill(층 구조·턴제 전투·특성 해금 메타). **본인이 직접 플레이해 본 게임이 아니면 인용 전에 직접 확인하거나 상세한 2차 자료를 읽고 인용**할 것 — 진행 메모의 "본인이 찾아 읽고 인용" 원칙과 동일한 적용.
2. **"익스트랙션 = 로그라이크 아님" 구분** — 구두시험에서 "Tarkov도 맵 랜덤이면 로그라이크 아닌가" 류 질문 가능. 고정 맵(또는 제한적 변형) + 보유 자산 반출 리스크가 핵심이라는 문장을 2.2.1에 선제적으로 넣어두면 방어됨.
3. **Lethal Company의 위치** — 순수 익스트랙션이라기보다 "리스크-보상 루프를 공유하는 인접 사례"이므로 인용 시 이 점을 스스로 구분해 둘 것(D 매트릭스에 넣을 때 행이 어색해지는 지점과 동일).

## 6. 기존 메모와의 정합성 (무엇이 바뀌고, 안 바뀜)

| 항목 | 변화 여부 |
|---|---|
| 진행 메모 §3의 2.2 배정(⑩절 메인 인용: Cuerdo/Chang/Zhang/Schell) | **변화 없음** — 게임 사례는 이 목록에 추가되는 것이지 교체 아님 |
| "신: 2.x(이론)/3.x(구현)" 분리 원칙 | 유지 — 게임의 *구현 구조 분석*은 3.6절로, 2.2에는 장르 정의 수준만 |
| Skyhill 비교표 | 확장 가능(D 방법 매트릭스) — 표 자체는 자산으로 재활용 |
| AI 활용 원칙 §2 | 충돌 없음 — 단 "본인이 직접 확인" 부담이 논문에서 게임으로 이동할 뿐 |

## 7. 결론 (3줄)

1. **게임 예시: 가능하고 효과적** — 다만 본문에 등장시키되, 각 사례마다 정식 인용 형식(제목·개발/발행사·연도)과 "SubwayExit의 어떤 구현 결정을 뒷받침하는가" 연결 문장 한 줄을 붙일 것.
2. **학술 인용 전량 대체: 비권고** — 2.2에는 Juul 계열 실패 이론(2.1과 분할 시 중복 주의), Cuerdo 또는 Chang 외, Zhang 중 최소 3개 앵커를 유지하고 게임은 "장르 정의·사례화" 층으로 배치.
3. **형식 확정 전 확인 두 가지** — (a) 학교/학과가 별도 "인용 작품" 목록을 허용하는지(방법 E), (b) Tarkov(LC 포함)의 EA 상태에 따른 연도 표기 관행, Skyhill 개발사·연도 확인.
