## 항목별 근거

### 1. 구역별 빠른 이동 — 미착수

`Object/BaseDepartureGate.cs` `OnConfirmed()`

```csharp
int idx = Random.Range(0, explorationStartPoints.Length);
```

여전히 무작위 시작점 선택이다. 해금 구역 목록도, 선택 UI도 없다.

### 2. 특성 해금 메타 진행 — 미착수

`Trait` / `Perk` 관련 스크립트와 ScriptableObject 에셋이 존재하지 않는다.
`Manager/GameManager.cs`의 영속 저장은 `settings.json` 하나뿐이며 저장 대상은 `GameSettings`(해상도·볼륨) 뿐이다.

```csharp
private string savePath => Path.Combine(Application.persistentDataPath, "settings.json");
```

세션 간 데이터를 보관할 수단 자체가 아직 없으므로, 이 항목은 저장 계층부터 새로 만들어야 한다. 남은 일정에서 가장 비용이 큰 작업.

### 3. 개명 + `GameClear()` 제거 — 절반 완료

개명은 되었다. 파일과 클래스 모두 `Blockade`다. 그러나 동작은 그대로다.

`Object/Blockade.cs` `OnInteractInternal()`

```csharp
GameManager.Instance.GameClear();
```

기본 메시지 문자열도 아직 탈출구용이다 (`"비상구 열쇠 필요"`, `"탈출"`).

한편 `Data/ItemInfo/Consumable/`에 **`탈출구 열쇠.asset`이 새로 생성**되어 기존 `비상구 열쇠.asset`과 공존한다. 열쇠를 분리하려던 작업의 흔적으로 보이며, 이 분리는 논문의 용어 정리와도 맞물린다.

참고로 **`BaseReturnExit.cs`가 실제 비상구**다. 열쇠를 소비하고 `CycleManager.ExecuteCycleReset()`을 호출해 기지로 귀환시킨다. 즉 현재 `Blockade`는 비상구가 아니라 최종 탈출구이고, 이름만 Blockade다.

### 4. 상속 구조 리팩토링 — 미착수

`Blockade : ItObjectBase` 그대로이며 자식 클래스가 없다. 3번과 함께 처리하는 것이 자연스럽다.

### 5. 2구역 최소 구현 — 미착수

`Assets/Scenes/`에 존재하는 씬은 `Base&Main1`, `SampleBattelTest`, `StartMenuScene`, `TutorialScene` 네 개다. 두 번째 구역에 해당하는 씬이나 구역 데이터가 없다.

논문 3.6 마지막 문단의 "새로운 구역 추가 시 기존 코드의 수정 없이 키 아이템과 보스의 루트 테이블만 추가하면 되므로 총 6개 구역을 수용할 수 있는 확장성을 확보하고 있다"는 서술은 현재 실증 근거가 없는 상태다.

### 6. 허기 커플링 버그 — 완료

`Status/PlayerStatus.cs`

```csharp
if (hungry <= 30) { curMaxCarryWeight = maxCarryWeight * 0.4f; }
else              { curMaxCarryWeight = maxCarryWeight; }
```

기준값이 `maxCarryWeight`로 고쳐졌고, 임계값을 벗어나면 원복하는 `else`도 들어갔다. 갈증 쪽도 동일하게 `MaxStamina * 0.4f` 기준이다.

### 7. 아이템 손실율 — 절반 완료

필드는 생겼다. `PlayerStatus.cs`에 `public float curdeathItemLossRate;`

그러나 소비하는 곳이 없다. `State/PlayerState/ActiveState/Die.cs`의 `RespawnRoutine()`은 HP 회복과 사이클 리셋만 수행하며 인벤토리를 건드리지 않는다.

```csharp
player.status.Hp = player.status.Maxhp;
CycleManager.Instance.ExecuteCycleReset();
```

씬에도 이 필드의 오버라이드 값이 없어 현재 0이다. 즉 사망해도 아이템은 여전히 전량 보존된다.

### 8. 탐지 게이지 50 — 검증 완료

`State/MonsterState/MonsterStateMachine.cs`

```csharp
public bool CanBeExecuted() => status.detection_gauge <= 50f;
```

게이지는 0~100 범위이며 논문 3.4의 "탐지 게이지 50 이하" 표기가 그대로 맞다. 수정 불필요.

### 9. parryDuration — 검증 완료, 논문 수정 필요

`Base&Main1.unity` 씬의 플레이어 오버라이드 값:

```yaml
propertyPath: status.parryduration
value: 0.3
```

실제 값은 **0.3초**다. 논문 3.4의 "0.4초" 표기를 0.3초로 고쳐야 한다.

### 10. 날것 섭취 페널티 — 검증 완료

`Data/ItemInfo/Consumable/생고기.asset`

```yaml
FillingAmount: 10
HealthAmount: -2
```

`Item/Food.cs`의 `OnUse()`가 `Hp += HealthAmount`를 수행하므로 생고기 섭취 시 체력이 2 감소한다. 논문 3.7의 "오염된 물이나 생고기 등은 그대로 섭취할 경우 체력이 감소하는 페널티" 서술이 맞다. 수정 불필요.

## 점검 중 새로 발견한 것

### A. 3.7 생존 상태값 감소율이 논문과 다르다 (우선 처리)

씬의 실제 오버라이드 값:

```yaml
status.hungerDecreasePerMinute: 0.3
status.waterDecreasePerMinute:  0.6
```

`HungerThirst.OnMinuteTick()`은 `GameManager.ChangeTime` 이벤트에 구독되어 있고, 이 이벤트는 게임 내 1분마다 발생한다. `GameManager.Clock()`이 실제 2.5초마다 1분을 증가시키므로 **실제 1분 = 게임 내 24분**이다.

따라서 실제시간 1분당 감소율은 다음과 같다.

| 상태값 | 게임 내 1분당 | 실제 1분당 | 임계값 30 도달 | 0 도달 |
|---|---|---|---|---|
| 허기 | 0.3 | **7.2** | 약 9.7분 | 약 13.9분 |
| 갈증 | 0.6 | **14.4** | 약 4.9분 | 약 6.9분 |

논문 표에 적힌 허기 2.4 / 갈증 7.2는 스크립트 기본값 0.1 / 0.3에 해당하는 옛 수치다. 그 뒤 씬에서 값이 상향되었고 비율도 1:3에서 1:2로 바뀌었다. **표를 위 값으로 갱신하거나, 씬 값을 논문 값에 맞춰 되돌리거나 둘 중 하나를 선택해야 한다.**

### B. 3.7 의존관계 표의 방향이 뒤집혀 있다 — 본문이 맞다

코드 기준 실제 연결은 다음과 같다.

- 허기 ≤ 30 → `curMaxCarryWeight` (최대 소지무게) × 0.4
- 갈증 ≤ 30 → `curMaxStamina` (최대 스태미나) × 0.4

논문 본문 서술이 이와 일치하고, **표가 반대로 적혀 있다.** 표를 고치면 된다.

참고로 씬의 `status.maxCarryWeight` 값은 80이다.

### C. 가드 피해 배율의 실제 값

`Guard.HandleDamage()`가 `Damage * GuardStrength`를 적용하므로 값이 클수록 피해가 크다. 실제 데이터 예시로 `WeaponStatus_Machete`의 `GuardStrength: 0.9`다. 논문에서 "경감률"로 쓰면 방향이 반대로 읽히므로 "가드 피해 배율"로 표기한다.

`WeaponStatus`에는 논문에 아직 언급되지 않은 `executionRange`, `execution_m`(처형 배율), `bloodStrenth`(출혈 강도)도 있다. 3.4에서 처형을 이미 다루므로 처형 배율은 파라미터 목록에 넣는 편이 서술과 맞는다. (`bloodStrenth`는 `bloodStrength` 오타)

### D. 오브젝트 풀링은 동작하지 않는다

`Manager/MonsterManager.cs`에 풀 자료구조와 `Preload` / `ReturnToPool`이 있으나,

```csharp
public enum MonsterType {}
```

열거형이 비어 있고 `MonsterStates.Die.LogicUpdate()`에는 `//몬스터 비활성화 후 몬스터 풀로 되돌림` 주석만 있을 뿐 호출이 없다. 3.9 최적화 절에 오브젝트 풀링을 구현 사항으로 적으면 안 된다.
