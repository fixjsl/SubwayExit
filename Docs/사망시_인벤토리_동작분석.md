# 플레이어 사망 시 인벤토리 동작 분석

> 조사일: 2026-09-16 · 대상 파일: `Die.cs`, `PlayerStateMachine.cs`, `Inventory.cs`, `CycleManager.cs`, `GameManager.cs`, `GameOverUI.cs`

## 결론 (TL;DR)

**플레이어가 사망해도 인벤토리에 일어나는 일은 아무것도 없다.**
아이템 드랍, 클리어, 저장이 모두 없으며, 리스폰 시에도 전량 그대로 보존된다.

---

## 1. 사망 플로우 전체 (`Die.cs`)

사망으로 `Die` 상태 진입 시 `Enter()`가 아래 순서로 실행됨.

| 순서 | 처리 | 목적 |
|---|---|---|
| 1 | `animator.CrossFade(player.die)`, `PlaySFX(deathSound)` | 사망 애니메이션 + 사운드 재생 |
| 2 | `Rb.linearVelocity = Vector3.zero`, `Rb.isKinematic = true` | 물리 이동 정지, 외력 적용 제외 |
| 3 | `gameObject.layer = Layercache.Die` | Die 레이어로 이동 (충돌/인터랙트 속성 변경) |
| 4 | `player.OnDisable()` | **`action?.Disable()` 호출뿐** — 입력 액션 비활성화. 인벤토리 관련 없음 |
| 5 | `status.Chance--` | 남은 사망 횟수 감소 |

이후 Chance 값에 따라 분기:

### Case A — Chance > 0 (리스폰)
`RespawnRoutine()` 코루틴으로 **2초 대기** 후:
- HP 풀 복구 (`Hp = Maxhp`)
- `CycleManager.ExecuteCycleReset()`:
  - 플레이어를 베이스 위치(`playerBasePosition`)로 텔레포트
  - 몬스터 리스폰 (보스 제외, 비활성 포함 탐색)
  - 컨테이너·출발 게이트 사이클 리셋
- 레이어를 Player로 복귀, kinematic 해제, 입력 재가동(`OnEnable()`), 상태 `Idle` 전환

### Case B — Chance == 0 (게임 오버)
- `GameManager.GameOver()` → `OnGameOver` 이벤트 발생
- 유일한 구독자: **`GameOverUI`** — 패널 표시 + `Time.timeScale = 0f`
- 메인 메뉴 버튼 → `SceneManager.LoadScene(mainMenuSceneName)`으로 씬 재로드

## 2. 인벤토리에 실제로 일어나는 일 — 아무것도 없음

1. **`Die.cs`에는 `inventory` 참조가 한 번도 없다.** 사망 시 드랍/클리어/저장 로직이 어디에도 존재하지 않음.
2. **`Inventory`은 일반 C# 클래스** (`PlayerStateMachine.Awake()`에서 `new Inventory(status)` 생성)이며, GameObject에 붙어 있는 MonoBehaviour이 아님. 플레이어 오브젝트 자체가 파괴되지 않으므로 사망 → 리스폰(동일 인스턴스) 시 `slots`, `QuickSlots`, `currentWeight`가 그대로 유지됨.
3. 즉, **아이템을 들고 죽어도 베이스에서 리스폰하며 동일 아이템을 그대로 소지**. 아이템 손실 페널티가 없음.
4. 게임 오버(Chance 소진) 경로에서도 인벤토리 전용 처리는 없고, 씬 재로드 시 플레이어 오브젝트와 함께 폐기되는 것뿐. `GameManager`의 저장 로직은 settings.json(`savePath`)만 다루며 **인벤토리의 세이브/로드는 존재하지 않음**.

---

## 3. 관련 부수 관찰 (리스크)

1. **사망 드랍 페널티 없음** — "죽으면 아이템 드랍", "사망 지점에 아이템 잔존" 같은 설계 의도가 있다면 현재 미구현 상태로, 리스폰 시 전량 보존됨.
2. `Inventory.DropItem()`은 `RemoveItem()`의 별칭일 뿐이라 **던진 아이템이 월드에 엔티티로 생성되지 않고 소멸**함. 현재는 우클릭 컨텍스트 메뉴(`ContextMenuUI`)에서만 사용되며, 사망 드랍 시스템을 만들 경우 이 "소멸" 동작을 그대로 재사용하게 됨(별도의 월드 스폰 기능 필요).
3. 게임 오버 시 씬 로드까지 플레이어 오브젝트가 kinematic + Die 레이어로 씬에 잔존 — 인벤토리 데이터도 거기 있으나 접근 불가 상태(실질적 영향 없음).

---

## 4. 사망 드랍 시스템을 만들 때의 방법 (최대 5가지)

| # | 방법 | 특징 |
|---|---|---|
| 1 | **전체 드랍** | `slots` 전체를 사망 지점에 월드 엔티티로 스폰. 페널리 최대, 베이스가 멀면 회수 불가 리스크 |
| 2 | **무작위 % 드랍** | 총 중량/개수 중 N%만 무작위 선택 드랍. 페널리와 좌절감 균형, 생존 게임에서 가장 일반적 |
| 3 | **태그별 선택 드랍** | 특정 태그(장비/소모품 등) 아이템만 드랍하고 기본 도구는 보존. 아이템 유형별 세밀한 컨트롤 가능 |
| 4 | **Chance 기반 변동 드랍** | 남은 Chance에 따라 드랍률 변화 (Chance 적을수록 많이 드랍). 게임 오버에 가까울수록 위험도가 커지는 그래디언트 생성 |
| 5 | **사망 지점 잔존 + 시간 제한 회수** | 사망 지점에 아이템이 일정 시간(X초) 동안 존재, 이후 소멸. 리스폰 후 회수 가능해 좌절감 완화 |

> 공통 전제: 위 방법 모두 현재 없는 **"월드에서 아이템 엔티티 생성(픽업)" 기능**이 필요함.
> `DropItem`은 슬롯 제거만 수행하므로, 월드 스폰 로직을 먼저 준비해야 함.
