## 1. 설계 결정 — `zones`를 누가 들 것인가

**`CycleManager`가 드는 것을 권합니다.** 지금은 출발 지점이 `BaseDepartureGate`에, 비상구 후보가 `CycleManager`에 흩어져 있는데, 구역 개념이 들어오면 둘이 한 몸이 됩니다. 사이클 상태의 주인이 `CycleManager`이니 거기로 모으세요.

- `CycleManager` — `zones` 배열 소유, 개방 구역 조회, 비상구 배치
- `BaseDepartureGate` — 선택 UI 띄우고 결과를 `CycleManager`에 넘기기만
- `ZoneSelectUI` — 버튼 표시

`BaseDepartureGate`의 `explorationStartPoints`는 제거되고 `CycleManager`의 `exitSpawnPoints`, `activeExit`도 제거됩니다. **diff가 커지는데 그게 정상이고, 그게 4.3.1의 증거입니다.**

## 2. `ZoneEntry` — 새 파일

`Assets/Script/Manager/ZoneEntry.cs`

```csharp
using UnityEngine;

[System.Serializable]
public class ZoneEntry        // struct 아님. 참조 비교(z == startZone)를 쓰기 때문
{
    public string zoneName;            // 빠른 이동 UI 표시용
    public Blockade gateBlockade;      // 이 구역을 막는 블록에이드. null이면 항상 개방
    public Transform[] startPoints;    // 출발 지점 후보
    public Transform[] exitPoints;     // 비상구 배치 후보
    public BaseReturnExit exit;        // 이 구역 전용 비상구

    public bool IsOpen =>
        gateBlockade == null || !gateBlockade.gameObject.activeSelf;
}
```

`IsOpen`이 이 설계의 핵심입니다. 블록에이드가 비활성화되어 있다는 사실이 곧 개방 신호이므로 별도 플래그도 저장도 필요 없습니다.

## 3. `CycleManager` 개조

제거할 필드: `activeExit`, `exitSpawnPoints`
제거할 메서드: `RelocateExitFarthestFrom`

```csharp
[SerializeField] private ZoneEntry[] zones;

public IReadOnlyList<ZoneEntry> Zones => zones;

public List<ZoneEntry> GetOpenZones()
{
    var result = new List<ZoneEntry>();
    foreach (var z in zones) if (z.IsOpen) result.Add(z);
    return result;
}

/// 출발 시 호출. 시작 구역의 비상구는 최원거리, 나머지 개방 구역은 무작위.
public void PlaceExits(ZoneEntry startZone, Vector3 startPos)
{
    foreach (var z in zones)
    {
        if (z.exit == null) continue;

        if (!z.IsOpen || z.exitPoints == null || z.exitPoints.Length == 0)
        {
            z.exit.gameObject.SetActive(false);
            continue;
        }

        Transform chosen;
        if (z == startZone)
        {
            chosen = z.exitPoints[0];
            float best = -1f;
            foreach (var p in z.exitPoints)
            {
                float d = Vector3.Distance(startPos, p.position);
                if (d > best) { best = d; chosen = p; }
            }
        }
        else
        {
            chosen = z.exitPoints[Random.Range(0, z.exitPoints.Length)];
        }

        z.exit.gameObject.SetActive(true);
        z.exit.transform.position = chosen.position;
        z.exit.ResetForCycle();
    }
}

/// 구역의 출발 지점 하나를 무작위로 고른다.
public Vector3 PickStartPoint(ZoneEntry zone, float spawnZ)
{
    Vector3 raw = zone.startPoints[Random.Range(0, zone.startPoints.Length)].position;
    return new Vector3(raw.x, raw.y, spawnZ);
}
```

`ExecuteCycleReset()`에 비상구 정리를 한 줄 추가하세요. 기지로 돌아온 뒤 다음 출발까지는 비상구가 떠 있을 이유가 없습니다.

```csharp
public void ExecuteCycleReset()
{
    TeleportPlayerToBase();
    RespawnMonsters();
    ResetContainers();
    HideAllExits();                                   // ← 추가
    if (departureGate != null) departureGate.ResetForCycle();
}

private void HideAllExits()
{
    foreach (var z in zones)
        if (z.exit != null) z.exit.gameObject.SetActive(false);
}
```

## 4. `BaseDepartureGate` 개조

`explorationStartPoints` 제거. `spawnZ`는 유지.

```csharp
private void OnConfirmed()
{
    var open = CycleManager.Instance.GetOpenZones();
    if (open.Count == 0) return;

    if (open.Count == 1) Depart(open[0]);
    else ZoneSelectUI.Instance.Show(open, Depart);
}

private void Depart(ZoneEntry zone)
{
    departed = true;
    RefreshPrompt();

    Vector3 startPos = CycleManager.Instance.PickStartPoint(zone, spawnZ);

    var player = PlayerStateMachine.Instance;
    player.Rb.position = startPos;
    player.Rb.linearVelocity = Vector3.zero;

    CycleManager.Instance.PlaceExits(zone, startPos);
}
```

구역이 하나뿐이면 선택 UI를 건너뛰므로 **지금과 동작이 완전히 같습니다.** 2구역을 배치하기 전에 이 상태로 먼저 돌려 보세요. 기존 동작이 깨지지 않았는지 확인한 뒤 씬 작업에 들어가는 게 안전합니다.

## 5. `ZoneSelectUI` — 새 파일

`Assets/Script/UI/ZoneSelectUI.cs`. `ConfirmUI`의 싱글턴 패턴과 `GameStartFlow`의 카드 컨테이너 방식을 섞으면 됩니다.

```csharp
using System;
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.UI;

public class ZoneSelectUI : MonoBehaviour
{
    public static ZoneSelectUI Instance { get; private set; }

    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
    static void ResetStatics() => Instance = null;

    [SerializeField] private GameObject panel;
    [SerializeField] private Transform buttonContainer;
    [SerializeField] private Button buttonPrefab;
    [SerializeField] private Button cancelButton;

    private Action<ZoneEntry> onSelected;

    void Awake()
    {
        Instance = this;
        panel.SetActive(false);
        cancelButton.onClick.AddListener(Hide);
    }

    public void Show(IReadOnlyList<ZoneEntry> zones, Action<ZoneEntry> callback)
    {
        onSelected = callback;

        foreach (Transform child in buttonContainer) Destroy(child.gameObject);

        foreach (var z in zones)
        {
            var zone = z;                              // 클로저 캡처 주의
            var btn = Instantiate(buttonPrefab, buttonContainer);
            btn.GetComponentInChildren<Text>().text = zone.zoneName;
            btn.onClick.AddListener(() => { Hide(); onSelected?.Invoke(zone); });
        }

        panel.SetActive(true);
    }

    private void Hide()
    {
        panel.SetActive(false);
        onSelected = null;
    }
}
```

`var zone = z;` 한 줄이 중요합니다. `foreach` 변수를 그대로 람다에 캡처하면 C# 버전에 따라 마지막 항목만 잡힐 수 있습니다.

TMP를 쓰시면 `Text`를 `TMP_Text`로 바꾸세요.

**취소 버튼을 꼭 두세요.** 출발 게이트에서 실수로 눌렀을 때 빠져나갈 길이 없으면 곤란합니다. 취소하면 `departed`가 false로 남아 다시 상호작용할 수 있어야 합니다.

## 6. 씬 작업

- 2구역 맵 배치
- 1→2구역을 막는 `Blockade` 프리팹 배치, `keyItem`에 보스 열쇠 지정

## 7. 테스트 체크리스트

**기존 동작 보존 (2구역 배치 전에)**

- [ ] 1구역만 있는 상태에서 출발 → 선택 UI 안 뜨고 바로 출발
- [ ] 비상구가 시작 지점에서 가장 먼 곳에 생기는지
- [ ] 비상구로 탈출 → 사이클 리셋 정상
- [ ] 사망 → 리셋 → 재출발 정상

**2구역 배치 후**

- [ ] 보스 처치 → 열쇠 획득 → 블록에이드 해제 → 2구역 통행 가능
- [ ] 기지로 돌아와 다시 출발 → 선택 UI 표시
- [ ] 1구역 선택 시 1구역 비상구는 최원거리, 2구역 비상구는 무작위
- [ ] 2구역 선택 시 반대로
- [ ] **다른 구역의 비상구로 탈출해도 사이클 리셋이 정상인지**
- [ ] 취소 버튼으로 빠져나온 뒤 다시 출발 가능한지
- [ ] 사이클 리셋 후에도 블록에이드가 해제 상태로 유지되는지
- [ ] 사망 후에도 블록에이드 해제 상태 유지되는지

마지막 두 개가 이 설계의 전제입니다. 여기서 깨지면 `IsOpen` 방식을 다시 봐야 합니다.
