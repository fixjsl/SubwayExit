## 1. 세션 종료 시 특성 2종 이월 (메타 진행) — 코드 없음

**표 8 3.5행:** "세션 종료 시 특성 2종 이월 메타 진행 연동" · 구현 여부 **완료**

**확인 방법과 결과.** `Assets/Script` 전체에서 `trait`, `특성`, `meta`, `이월`, `carryover`, `progress`, `PlayerPrefs`, `SaveGame`을 검색한 결과 **일치 항목 0건**입니다.

세이브 시스템 자체가 없습니다. `GameManager`가 `settings.json`을 읽고 쓰지만 내용은 해상도·창모드·품질·볼륨 네 가지뿐이고(`GameSettings` 클래스), 게임 진행과는 무관합니다. `GameOverUI`는 패널을 띄우고 메인 메뉴 씬으로 돌아갈 뿐 아무것도 저장하지 않습니다.

**판단.** 이월할 특성을 정의하고, 세션 종료 시 저장하고, 다음 세션 시작 시 적용하는 세 단계가 전부 필요합니다. 새 세이브 파일 포맷도 있어야 합니다. **이번 주에 붙이기에는 가장 큰 작업입니다.**

현실적인 선택지는 둘입니다. 특성 2종을 아주 단순하게(예: 최대 체력 +10, 시작 아이템 1종) 정의하고 `settings.json` 옆에 `progress.json` 하나 더 쓰는 수준으로 최소 구현하거나, 아니면 표 8을 "부분 완료"로 바꾸고 3.5절 본문에서 "설계하였으나 구현에 이르지 못하였다"로 서술을 조정한 뒤 5.2절 향후 과제로 넘기는 것입니다.

## 2. 사망 시 아이템 75% 소실 — 필드만 있고 로직 없음

**표 8 3.5행:** "사망 시 아이템 75% 소실 및 기지 리셋" · 구현 여부 **완료**

**확인 결과.** `PlayerStatus.cs` 126번째 줄에 필드가 선언되어 있습니다.

```csharp
public float curdeathItemLossRate;
```

그런데 이 필드를 **읽는 곳이 코드베이스 어디에도 없습니다.** 선언 한 줄이 전부입니다.

사망 처리인 `Die.cs`는 이렇게만 합니다.

```csharp
player.status.Chance--;
if (player.status.Chance > 0) player.StartCoroutine(RespawnRoutine());
else GameManager.Instance.GameOver();
// RespawnRoutine: HP 회복 → CycleManager.ExecuteCycleReset() → Idle
```

인벤토리를 건드리는 코드가 없습니다. **"기지 리셋"은 구현되어 있고, "아이템 75% 소실"만 빠져 있습니다.**

**판단.** 이건 작업량이 작습니다. `Die.Enter()`나 `RespawnRoutine()`에서 `inventory.slots`를 순회하며 `curdeathItemLossRate` 비율만큼 `RemoveItem`을 호출하면 됩니다. 소수점 처리와 퀵슬롯 정리(`ClearQuickSlotIfEmpty`는 `RemoveItem` 안에서 이미 불립니다)만 신경 쓰면 반나절 안에 끝납니다.

**이번 주 안에 하시는 걸 권합니다.** 필드가 이미 있어서 "설계는 했는데 연결을 안 했다"가 그대로 드러나는 상태라 지적당하기 쉽고, 고치는 비용은 가장 쌉니다.

## 3. 기지 빠른 이동 — 코드 없음

**표 8 3.6행:** "보스 처치 아이템 기반 영구 개방 및 기지 빠른 이동 연동" · 구현 여부 **완료**

**확인 결과.** `teleport`, `warp`, `fasttravel`, `빠른`을 검색하면 `CycleManager`의 `TeleportPlayerToBase()` 하나만 나옵니다. 이것은 **비상구로 귀환할 때 플레이어를 기지 좌표로 옮기는 사이클 리셋 전용 함수**이고, 구역 간 빠른 이동과는 다른 기능입니다.

`Doorcs`는 단순 여닫이 문, `StairObject`는 계단 이동, `BaseDepartureGate`는 기지에서 나갈 때 무작위 시작 지점을 고르는 출발 게이트입니다. 구역을 선택해 이동하는 수단이 없습니다.

**이번 주 작업 대상이라고 하셨으니 그대로 진행하시면 됩니다.** 다만 아래 6번과 함께 설계하셔야 합니다.

## 4. 블록에이드 중간 상태(IOB) — 2단계만 구현

**표 8 3.6행:** "SOB → (IOB) → DOB 단순화 블록에이드 메커니즘"

**확인 결과.** `Blockade.cs`는 잠김/해제 두 상태뿐입니다.

```csharp
protected virtual void BlockadeInteract()
{
    PlayerStateMachine.Instance.inventory.RemoveItem(keyItem, 1);
    gameObject.SetActive(false);
}
```

`Blockade`를 상속한 클래스도 없습니다. 중간 상태(IOB)는 구현되어 있지 않습니다.

**판단.** 표 8에 "단순화"라고 적으셨고 IOB를 괄호로 묶으셨으니, 3.6절 본문이 "IOB는 생략하고 단순화하였다"로 서술되어 있으면 문제없습니다. **3.6절 원문만 확인해 주세요.** 만약 IOB가 구현된 것처럼 서술되어 있으면 고쳐야 합니다.

`BlockadeInteract()`가 `virtual`이라 필요해지면 상속으로 쉽게 붙일 수 있다는 점은 4.3.1에서 언급할 만합니다.

## 5. 구역 2개 이상 — 이번 주 작업

**표 8 3.6행:** "부분 완료 (검증 완료) · 현재 1개 구역 중심으로 구현"

구조적으로는 준비가 되어 있습니다. 구역 식별자(enum, ID, 상수)가 코드베이스에 **하나도 없고**, 구역은 씬 배치와 `Transform[]` 배열로만 표현됩니다. `Blockade`의 열쇠 아이템과 메시지가 전부 `SerializeField`이므로 새 블록에이드는 프리팹과 ScriptableObject만으로 만들어집니다.

**따라서 구역 추가 자체는 코드 수정 0줄이 유력합니다.** 이게 4.3.1의 핵심 증거가 됩니다.

## 6. 비상구 배치 규칙의 다구역 대응 — 구역 나누기 전에 결정해야 함

**이건 3장에 서술되지 않은 항목인데, 구역을 나누는 순간 반드시 마주치게 됩니다.**

`CycleManager.RelocateExitFarthestFrom()`이 이렇게 동작합니다.

```csharp
for (int i = 0; i < exitSpawnPoints.Length; i++)
{
    float dist = Vector3.Distance(origin, exitSpawnPoints[i].position);
    if (dist > bestDist) { bestDist = dist; bestIndex = i; }
}
```

**전체 후보 중 시작 지점에서 가장 먼 곳**을 무조건 고릅니다. 구역이 둘 이상이 되면 두 가지 문제가 생깁니다.

첫째, 아직 열지 않은 구역의 후보가 선택될 수 있습니다. 그러면 비상구에 도달할 방법이 없어 사이클이 막힙니다.

둘째, "가장 먼 곳"이 항상 최신 구역이 되어 탈출 경로가 매번 같아집니다. 3.5절이 강조한 무작위성이 사라집니다.

**구역을 나누기 전에 규칙을 정하셔야 합니다.** 후보를 구역별로 묶고 개방된 구역 안에서만 고르는 방식, 또는 개방된 구역 전체를 대상으로 하되 거리 가중 무작위로 바꾸는 방식 등이 있습니다.

이 항목은 **4.3.1에서 가장 값진 결과가 됩니다.** "데이터만으로 확장되지만 사이클 규칙은 단일 구역을 전제로 작성되어 있었다"는 구체적인 발견이고, 그대로 5.2절로 이어집니다. 그러니 고치더라도 **고치기 전 상태를 기록해 두세요.** 실험 C의 커밋 diff에 이 수정이 포함되면 그것 자체가 증거입니다.

## 확인 결과 구현되어 있는 것

불필요하게 다시 만들지 않도록 적어 둡니다.

- **3회 목숨 완충.** `PlayerStatus.Chance = 3`, `Die.cs`에서 감소 후 `Chance > 0`이면 부활, 아니면 `GameOver()`. 정상 동작합니다.
- **사망 시 기지 리셋.** `Die.RespawnRoutine()`이 `CycleManager.ExecuteCycleReset()`을 호출하여 플레이어 귀환·몬스터 리스폰·컨테이너 복구를 수행합니다.
- **보스 처치 아이템 기반 영구 개방.** `Blockade`가 `SetActive(false)`로 사라지고, `CycleManager`는 몬스터와 컨테이너만 되돌리므로 블록에이드는 해제 상태로 유지됩니다.
- **무작위 시작 지점.** `BaseDepartureGate`가 `explorationStartPoints` 중 하나를 무작위 선택합니다.
- **디버그 덤프 가드.** `[DEBUG STATUS]`, `[MONSTER DEBUG]`, `[BOSS DEBUG]`, 인벤토리 덤프 모두 `#if UNITY_EDITOR`로 감싸져 있어 빌드에 들어가지 않습니다.
