## 1. 사망 시 아이템 손실

### 확정된 규칙

- **아이템 종류별 75%가 아니라, 인벤토리 전체 수량 합의 75%.** 따라서 특정 아이템이 전량 사라질 수 있다.
- **유니크 아이템(런당 하나만 등장)은 무조건 전량 소실.**

### 먼저 해결할 것 — 유니크 판정을 어디서 가져오나

유니크 토글은 이미 있습니다. 다만 `ItemBase`가 아니라 `LootTable.cs`의 `LootEntry`에 붙어 있습니다.

```csharp
public class LootEntry
{
    public ItemBase item;
    ...
    public bool isUnique = false;
}
```

그리고 `LootTable`이 런당 중복 드롭을 막으려고 static 집합을 들고 있습니다.

```csharp
private static readonly HashSet<int> droppedUniqueItemCodes = new();
```

**`Die.cs`는 인벤토리의 아이템 코드만 알기 때문에, 이 정보 없이는 유니크 여부를 판정할 수 없습니다.** 둘 중 하나를 고르세요.

**방법 A — `LootTable`의 집합을 공개한다 (권장, 변경 최소)**

```csharp
// LootTable.cs
public static bool IsUniqueItem(int itemcode) => droppedUniqueItemCodes.Contains(itemcode);
public static void ResetUniquesForNewSession() => droppedUniqueItemCodes.Clear();
```

이미 있는 자료를 그대로 씁니다. 두 줄이면 됩니다.

**방법 B — `ItemBase`에 `isUnique`를 올린다**

```csharp
// ItemBase.cs
public bool isUnique;
```

의미가 더 명확하지만, `LootEntry.isUnique`와 중복되므로 `LootTable.Roll()`이 `entry.item.isUnique`를 보도록 함께 고쳐야 합니다. 에셋의 토글도 전부 옮겨야 하고요. **시간이 없으면 A로 가세요.**

### 같이 고쳐야 할 버그

`droppedUniqueItemCodes`의 초기화가 이렇게 되어 있습니다.

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetUniques() => droppedUniqueItemCodes.Clear();
```

이건 **앱 실행당 한 번**만 돕니다. 게임오버 후 메인 메뉴로 나갔다가 새 게임을 시작해도 기록이 남아, 유니크 아이템이 다시 드롭되지 않습니다. 특성 이월을 붙이면 세션 경계가 생기므로 반드시 드러나는 문제입니다.

위 방법 A의 `ResetUniquesForNewSession()`을 만들고, `GameStartFlow.OnWeaponSelected()`에서 불러 주세요.

### 붙일 자리

`State/PlayerState/ActiveState/Die.cs`의 `Enter()`, `player.status.Chance--;` 바로 앞.

`RespawnRoutine()`이 아니라 `Enter()`에 두는 이유는 마지막 목숨으로 게임오버가 되는 경우에도 손실이 적용되어야 일관되기 때문입니다.

### 구현

```csharp
private void LoseItems()
{
    var inv = player.inventory;
    float rate = player.status.curdeathItemLossRate;
    if (rate <= 0f) return;

    // 1. 스냅숏. slots를 순회하며 RemoveItem을 부르면 컬렉션이 수정되어 예외가 난다.
    var entries = new List<(ItemBase item, int count)>();
    int total = 0;
    foreach (var pair in inv.slots)
    {
        if (!ItemManager.itemDB.TryGetValue(pair.Key, out var item)) continue;
        entries.Add((item, pair.Value));
        total += pair.Value;
    }
    if (total == 0) return;

    int target = Mathf.FloorToInt(total * rate);

    // 2. 유니크는 무조건 전량 소실. 나머지는 개수만큼 펼쳐 후보 풀에 담는다.
    var pool = new List<ItemBase>();
    int removed = 0;
    foreach (var (item, count) in entries)
    {
        if (LootTable.IsUniqueItem(item.itemcode))
        {
            inv.RemoveItem(item, count);
            removed += count;
        }
        else
        {
            for (int i = 0; i < count; i++) pool.Add(item);
        }
    }

    // 3. 남은 몫을 후보 풀에서 무작위로 뽑아 하나씩 제거한다.
    int remain = Mathf.Min(Mathf.Max(0, target - removed), pool.Count);
    for (int i = 0; i < remain; i++)
    {
        int idx = Random.Range(0, pool.Count);
        inv.RemoveItem(pool[idx], 1);
        pool.RemoveAt(idx);
    }
}
```

개수만큼 펼친 풀에서 뽑기 때문에 **많이 가진 아이템이 많이 사라지고, 운이 나쁘면 특정 아이템이 전량 사라집니다.** 확정하신 규칙 그대로입니다.

`using System.Collections.Generic;`를 추가하세요. `Die.cs`는 현재 `System.Collections`와 `UnityEngine`만 가져옵니다. `Random`은 `UnityEngine.Random`으로 해석되므로 그대로 두면 됩니다.

### 확인된 사실

- `PlayerStateMachine.inventory`는 외부 접근 가능합니다. `Blockade.cs`가 이미 씁니다.
- `ItemManager.itemDB`가 `int → ItemBase` 사전입니다.
- 퀵슬롯 정리는 `RemoveItem` 안의 `ClearQuickSlotIfEmpty`가 처리합니다.
- 장착 무기는 인벤토리 밖(`Weapon` MonoBehaviour)이라 영향 없습니다.

### 확인해 주실 것 두 가지

**`curdeathItemLossRate`가 인스펙터에서 실제로 0.75인지.** 지금은 아무도 읽지 않는 필드라 0으로 방치돼 있을 가능성이 큽니다. 0이면 코드를 붙여도 조용히 아무 일도 안 일어납니다.

**보스 열쇠를 쓰기 전에 죽으면 어떻게 되는지.** 블록에이드 열쇠가 유니크라면 사망 시 무조건 사라지고, `droppedUniqueItemCodes`에 이미 기록되어 있어 다시 드롭되지도 않습니다. **보스를 다시 잡아도 열쇠가 안 나와 구역이 영영 안 열립니다.** 의도한 난이도가 아니라면, 블록에이드 열쇠만 유니크에서 빼거나 손실 예외로 두어야 합니다. 이건 꼭 확인하세요.

## 2. 구역 분할 + 비상구 다중화 + 기지 빠른 이동

### 확정된 규칙

- **빠른 이동은 시작 위치만 결정한다.**
- **비상구는 개방된 구역마다 하나씩 생성된다.**
- **시작 위치가 있는 구역의 비상구는 시작 지점에서 가장 먼 곳에 배치한다.**
- **다른 구역의 비상구는 무작위로 배치한다.**

이 규칙이 좋은 이유가 하나 있습니다. 구역을 열수록 탈출 경로의 선택지가 늘어나고, 플레이어가 "다른 구역으로 건너가 탈출할지"를 판단하게 됩니다. **메트로배니아식 공간 확장이 탐색뿐 아니라 탈출 설계에도 영향을 준다는 이야기가 3.6절과 5.2절에 그대로 쓸 재료가 됩니다.**

### 자료구조

```csharp
[System.Serializable]
public class ZoneEntry          // struct 아닌 class 권장. 복사 혼란을 피할 것
{
    public string zoneName;            // 빠른 이동 UI 표시용
    public Blockade gateBlockade;      // 이 구역을 막는 블록에이드. null이면 항상 개방
    public Transform[] startPoints;    // 출발 지점 후보
    public Transform[] exitPoints;     // 비상구 배치 후보
    public BaseReturnExit exit;        // 이 구역 전용 비상구 오브젝트

    public bool IsOpen =>
        gateBlockade == null || !gateBlockade.gameObject.activeSelf;
}
```

**핵심은 `IsOpen`입니다.** 블록에이드가 비활성화되어 있다는 사실 자체를 개방 신호로 씁니다. `Blockade.BlockadeInteract()`가 `SetActive(false)`를 하고 `CycleManager`는 몬스터와 컨테이너만 되돌리므로, 해제 상태가 그대로 유지됩니다. **별도 플래그도 저장도 필요 없습니다.**

### 고쳐야 하는 기존 코드

**`BaseDepartureGate.cs`** — `explorationStartPoints`를 `ZoneEntry[] zones`로 교체

```csharp
[SerializeField] private ZoneEntry[] zones;

private void OnConfirmed()
{
    var open = new List<ZoneEntry>();
    foreach (var z in zones) if (z.IsOpen) open.Add(z);

    if (open.Count <= 1) Depart(open.Count == 1 ? open[0] : zones[0]);
    else ZoneSelectUI.Instance.Show(open, Depart);
}

private void Depart(ZoneEntry startZone)
{
    departed = true;
    RefreshPrompt();

    Vector3 raw = startZone.startPoints[Random.Range(0, startZone.startPoints.Length)].position;
    Vector3 startPos = new Vector3(raw.x, raw.y, spawnZ);

    var player = PlayerStateMachine.Instance;
    player.Rb.position = startPos;
    player.Rb.linearVelocity = Vector3.zero;

    CycleManager.Instance.PlaceExits(zones, startZone, startPos);
}
```

**`CycleManager.cs`** — `RelocateExitFarthestFrom`을 `PlaceExits`로 교체

기존 함수는 전체 후보 중 무조건 가장 먼 곳 하나를 골라 단일 `activeExit`을 옮겼습니다. 이제 구역마다 비상구가 따로 있으므로 구조가 바뀝니다.

```csharp
public void PlaceExits(ZoneEntry[] zones, ZoneEntry startZone, Vector3 startPos)
{
    foreach (var z in zones)
    {
        if (z.exit == null) continue;

        if (!z.IsOpen) { z.exit.gameObject.SetActive(false); continue; }
        if (z.exitPoints == null || z.exitPoints.Length == 0) { z.exit.gameObject.SetActive(false); continue; }

        Transform chosen;
        if (z == startZone)
        {
            // 시작 구역: 시작 지점에서 가장 먼 후보
            chosen = z.exitPoints[0];
            float best = -1f;
            foreach (var p in z.exitPoints)
            {
                float d = Vector3.Distance(startPos, p.position);
                if (d > best) { best = d; chosen = p; }
            }
        }
        else
        {
            // 다른 구역: 무작위
            chosen = z.exitPoints[Random.Range(0, z.exitPoints.Length)];
        }

        z.exit.gameObject.SetActive(true);
        z.exit.transform.position = chosen.position;
        z.exit.ResetForCycle();
    }
}
```

`CycleManager`의 기존 `activeExit`과 `exitSpawnPoints` 필드는 제거합니다.

## 3. 특성 2종 이월 (메타 진행)

### 먼저 확인할 것

3.5절 본문에서 "특성 2종 이월"이 플레이어가 고르는 것인지, 자동으로 정해지는 것인지 확인하세요. 아래는 전자 기준이며, 후자면 선택 UI가 빠져 반나절로 줄어듭니다.

### 새 파일 세 개

**`Script/Status/Trait.cs`**

```csharp
[CreateAssetMenu(fileName = "Trait", menuName = "Scriptable Objects/Trait")]
public class Trait : ScriptableObject
{
    public int traitId;
    public string traitName;
    [TextArea(2, 4)] public string description;

    [Header("효과")]
    public int maxHpBonus;
    public int maxStaminaBonus;
    public float carryWeightBonus;
    public ItemBase startingItem;

    public void Apply(PlayerStatus status, Inventory inventory)
    {
        status.Maxhp += maxHpBonus;
        status.MaxStamina += maxStaminaBonus;
        status.maxCarryWeight += carryWeightBonus;
        if (startingItem != null) inventory.AddItem(startingItem);
    }
}
```

효과를 이 넷으로 좁히면 `PlayerStatus`를 건드리지 않고 끝납니다. **범위를 넓히지 마세요.**

**`Script/Manager/MetaProgress.cs`**

```csharp
[System.Serializable]
public class MetaProgress
{
    public int carriedTraitA = -1;   // traitId. -1이면 없음
    public int carriedTraitB = -1;
}
```

**`Script/Manager/MetaProgressManager.cs`** — `GameManager`의 설정 저장 패턴을 그대로 복사

```csharp
public class MetaProgressManager : MonoBehaviour
{
    public static MetaProgressManager Instance { get; private set; }

    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
    static void ResetStatics() => Instance = null;

    [SerializeField] private Trait[] allTraits;
    public MetaProgress progress { get; private set; } = new MetaProgress();

    private string savePath => Path.Combine(Application.persistentDataPath, "progress.json");

    void Awake()
    {
        if (Instance == null) { Instance = this; DontDestroyOnLoad(gameObject); }
        else { Destroy(gameObject); return; }
        Load();
    }

    void Load()
    {
        if (File.Exists(savePath))
            JsonUtility.FromJsonOverwrite(File.ReadAllText(savePath), progress);
    }

    public void Save() => File.WriteAllText(savePath, JsonUtility.ToJson(progress, true));

    public void SetCarried(int idA, int idB)
    {
        progress.carriedTraitA = idA;
        progress.carriedTraitB = idB;
        Save();
    }

    public void ApplyCarried(PlayerStatus status, Inventory inventory)
    {
        ApplyOne(progress.carriedTraitA, status, inventory);
        ApplyOne(progress.carriedTraitB, status, inventory);
    }

    private void ApplyOne(int id, PlayerStatus status, Inventory inventory)
    {
        if (id < 0) return;
        foreach (var t in allTraits)
            if (t.traitId == id) { t.Apply(status, inventory); return; }
    }
}
```

### 연결 지점 두 곳

**세션 종료 → 선택 → 저장.** `GameManager`에 `OnGameOver`와 `OnGameClear` 이벤트가 이미 있습니다. `GameOverUI.Show()`가 그 이벤트를 구독하는 구조이므로, 같은 자리에서 특성 선택 UI를 띄우고 `SetCarried(...)`를 부르면 됩니다.

**세션 시작 → 적용.** `GameStartFlow.OnWeaponSelected()`가 게임이 실제로 시작되는 지점입니다.

```csharp
public void OnWeaponSelected()
{
    weaponCardContainer.SetActive(false);
    PlayerStateMachine.Instance.SetMovementLocked(false);

    LootTable.ResetUniquesForNewSession();           // ← 1절의 버그 수정

    var player = PlayerStateMachine.Instance;
    MetaProgressManager.Instance.ApplyCarried(player.status, player.inventory);
    player.status.Hp = player.status.Maxhp;          // Maxhp를 올렸으므로 다시 채움

    Time.timeScale = 1f;
    GameManager.Instance.TutorialStart();
}
```

`PlayerStatus.Hp`의 setter가 `Maxhp`로 클램프하므로 마지막 줄이 필요합니다.
