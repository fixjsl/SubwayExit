# 4.3절 성능 측정 계획

작성 2026-09-21 · 대상: 「익스트랙션 사이클 루프와 메트로배니아 공간 확장을 결합한 서바이벌 게임의 설계 및 구현」 4.3절

---

## 0. 시작 전 반드시 할 것

### 빌드 설정
- [ ] Build Profiles → **Script Debugging 해제** (켜져 있으면 JIT 최적화가 억제되어 프레임 시간이 부풀려짐)
- [ ] **Wait For Managed Debugger 해제**
- [ ] Development Build은 **유지** (PerfLogger의 ProfilerRecorder 카운터가 개발 빌드에서만 수집됨)
- [ ] Player Settings → Fullscreen Mode → **Windowed**
- [ ] PerfLogger의 `showOverlay = false`

### 측정 조건 확정
- [ ] **Frame Debugger로 `_PointLightCount` 실측값 확인**
  Window → Analysis → Frame Debugger → Enable → `FlashlightPass` 선택 → 셰이더 프로퍼티에서 값 읽기
  → 비상구 표지등(초록색, range 0.13, intensity 0.8)이 상시 등록되어 있으면 "0개" 조건이 실제로는 1개임.
  표의 조건 라벨을 이 실측값으로 확정할 것.
- [ ] 하이어라키 검색창에 `t:ScreenPointLight` 를 입력해 씬의 국소광원 전체 목록 확인

### 측정 공통 규칙
- 조건당 **3런** (1런만 재면 잡음과 효과를 구분할 수 없음 — 런 간 변동이 약 0.06ms / 3%로 확인됨)
- 예열 5초 + 측정 30초 (현재 PerfLogger 설정 그대로)
- 플레이어는 **같은 자리에 세워두고 조작하지 않음** (시야에 드는 오브젝트가 달라지면 그게 곧 잡음)
- 프로파일러 **미연결** 상태 (M2 제외 — 연결 자체가 프레임 시간을 늘림)
- 지표는 3.9절이 선언한 Koulaxidis & Xinogalos(2022)의 세 축을 반드시 포함: **FPS · 배치 수 · 삼각형 수**

## 1. 필수 측정 — 하지 않으면 3장의 약속이 빈다

### M1. 기본 성능
| 항목 | 내용 |
|---|---|
| 목적 | "이 게임이 몇 FPS로 동작하는가"라는 기본 수치. 성능 절의 첫 표 |
| 조건 | 대표 구간 3곳(기지 / 탐색 구역 / 보스 전투) × 3런 = 9런 |
| 지표 | 평균·중앙 프레임 시간, 95·99퍼센타일, 평균 FPS, 배치, 삼각형, 프레임당 GC |
| 대응 서술 | 4.3 도입부 전반 |
| 상태 | 미착수 |

> 지금까지 찍은 런은 전부 광원 조건 비교라 이 기본 수치가 없음.

### M2. 조명 합성 패스의 실행 비용
| 항목 | 내용 |
|---|---|
| 목적 | 3.9절 "4장에서는 조명 패스의 실행 비용을 직접 측정하고" — 명시적 약속 |
| 방법 | 프로파일러 창을 빌드에 연결 → CPU Usage → Hierarchy → **스레드를 Render Thread로 변경** → 검색창에 `FlashlightPass` |
| 평균 산출 | Package Manager에서 **Profile Analyzer** 설치 → Pull Data → 마커별 Median/Mean/Min/Max |
| 추가 | 화면 복사 패스(`AddBlitPass`)도 같은 캡처에서 함께 읽을 것 |
| 주의 | `Deep Profile` 버튼은 누르지 말 것 (오버헤드 수 배) · Frame Count를 2000으로 상향 |
| 상태 | 미착수 |

> ProfilerRecorder로는 수집 불가 확인됨 — 한 런 안에서 소수점 4자리까지 단일값으로 고정되어 나옴.

| 조건 | 동일 구간·동일 위치에서 SSAO 켠 빌드 3런 / 끈 빌드 3런 = 6런 |

### M4. 국소광원 수에 따른 부하
| 항목 | 내용 |
|---|---|
| 목적 | 3.9절 "반복문이 실제 등록된 광원 수만큼만 돈다", "광원이 없으면 반복문 자체가 수행되지 않는다", `MaxLights = 4`의 근거 |
| 조건 | ① 기준(광원 최소) ② 모닥불 배치 ③ **빈 오브젝트에 광원 컴포넌트만** — 각 3런 |
| 핵심 | ③이 ①과 드로우콜·SetPass·GC에서 일치해야 주장이 성립. 연출 오브젝트를 배제한 통제 조건 |
| 지표 | 드로우콜, 배치, SetPass, 삼각형, 프레임당 GC, 프레임 시간 |
| 상태 | **부분 완료** — Script Debugging 켠 상태였고 조건 라벨 미확정. 재측정 필요 |

> 기확보 결과(참고): 광원 컴포넌트만 3개 추가 시 드로우콜 62 · SetPass 39 · GC 1,204B로 기준 조건과 완전 일치.
> 모닥불 프리팹 추가 시 드로우콜 +14는 파티클 2 + 그 외 렌더러 12에서 발생(파티클 가설은 측정으로 기각됨).

## 4. 분량 견적

| 구간 | 런 수 | 순수 측정 시간 |
|---|---|---|
| 필수 (M1·M3·M4) | 21런 | 약 13분 |
| M2·M6 | 프로파일러 캡처 2회 | 약 5분 |
| 권장 (M5) | 6런 | 약 4분 |
| 선택 (M7·M8) | 10런 | 약 6분 |

실제로 시간을 먹는 건 측정이 아니라 **빌드와 조건 세팅**이다. SSAO 빌드와 정적 캐시 빌드를 미리 다 만들어두고 한 번에 도는 편이 훨씬 빠르다.

## 5. 결과 정리 시 주의

- **GC는 조건 비교 변수로 쓰지 말 것.** 런 사이에 통제되지 않는 것이 확인됨(파티클을 껐는데 GC가 오히려 +17% 증가). 절대값 수준으로만 서술할 것.
- **최대 프레임 시간은 단발 이상치가 섞인다.** 논문 표에는 99퍼센타일을 쓰거나, 최대값을 쓰되 이상치임을 각주로 밝힐 것.
- **드로우콜이 0으로 찍힌 프레임**은 항상 다음 프레임이 2배값으로 나오는 수집 아티팩트다. 1만 프레임 중 몇 개 수준이라 평균에 영향 없음.
- **개발 빌드 한계는 각주로 명시.** "측정은 프로파일러 계측이 활성화된 개발 빌드에서 수행되었으므로, 배포 빌드의 실제 성능은 이보다 높을 것으로 예상된다."
- **조건 D(광원 컴포넌트만)에는 실행 화면 스크린샷이 필요하다.** 빛 웅덩이가 실제로 보이는 화면이 없으면 "광원을 등록했지만 켜지지 않았다"는 반론에 답할 수 없다.
